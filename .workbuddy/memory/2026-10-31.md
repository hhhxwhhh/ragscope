### 关键约定（后续改动请遵守）

- 检索只有一个入口 `app/rag/pipeline.retrieve()`；单轮/Agent/深度/MCP/public 全部复用它，
  否则指标与 trace 口径会分叉。
- 多智能体图只决定「收什么证据」，最终回答永远走 grounded Prompt，保证引用编号与
  `citation_stats` 三种模式一致。
- MCP 与 `/public/*` 只读；写操作只在 Web 端。
- 后端指标标签必须用路由模板，禁止裸路径。
- 图扩展的候选追加在重排结果之后，不参与重排排序。

关键设计（后续别破坏）：
- 增量同步身份是 `(kb_id, external_url)`，版本是正文 sha256；unchanged 不触发 embedding。
- 删除数据源不删文档（documents.source_id ON DELETE SET NULL）。
- 语义缓存必须连同 candidates 一起存/还原，否则 [n] 引用会错位；只在首轮生效。
- 预算检查必须在语义缓存之后；流式 429、JSON 降级为拒答。
- webhook 的 notify 永不抛异常；投递失败只写 last_status/last_error。

### 关键：测试套件首次跑通（193 条单元测试全绿）

原因：`conftest.py` 在 `pytest_sessionstart` 里无条件连 PostgreSQL，而该钩子在收集
用例之前执行 → 纯单元测试也必崩 → 三个既有缺陷一直没暴露。
修复：改到 `pytest_collection_modifyitems`，只有收集到 integration 用例才建库跑迁移。
由此发现并修复：
1. `metrics._CounterChild` 缺 `value()` → 运维快照接口必然 500
2. 爬虫 `_SKIP_EXTENSIONS` 漏 .pdf/.docx 等 → 会抓无法解析的二进制
3. 中文分词把连续汉字当成一个 token → 压缩与打分失效

### 踩坑

- OOXML 有两个关系命名空间：`r:id` 用 officeDocument，`.rels` 文件用 package。
  写错不报错，只静默返回「找不到工作表/幻灯片」
- PPTX 页序必须走 `presentation.xml` 的 sldIdLst + rels，文件名序不等于页序
- H1 前置块清洗规则最初按「任意标题」判定，会删掉以列表开头的正文（单测当场抓到）
- 运行 crawl_corpus.py 需要 `PYTHONPATH=.`（脚本 `from app...`）
- cn.vite.dev 可访问；fastapi.tiangolo.com / docs.python.org 仍不可达
