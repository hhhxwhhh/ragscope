# 2026-11-01 工作日志

## 主线：把评测从「能说明流程」推进到「能支撑结论」

### 1. 标注集 26 → 80 条，gold 支持跨文档

`backend/scripts/make_eval_dataset.py` 的用例结构从
`(question, 单一定位串, chunk 索引, notes)` 改成
`(question, ((定位串, chunk 索引), ...), notes)`——**一条用例的 gold 可以跨多篇文档**。

动机：语义互相干扰的用例（命名路由 vs 命名视图、重定向 vs 别名、Pinia 的
State/Getter/Action）答案天然横跨多篇文档，只标单篇测不出语义检索和关键词匹配的差别。

`_resolve()` 先试完整 URL 精确匹配，再退到子串匹配。必须这么做：Pinia 的
`/zh/core-concepts` 是 `/zh/core-concepts/state.html` 的前缀，任何子串都不唯一。
定位歧义一律 `SystemExit`，拒绝猜。

最终 80 条 = 70 可答 + 10 不可答。

### 2. 新增 scripts/run_eval.py —— 评测变成可离线重跑的命令

之前评测只能靠临时代码触发。`run_eval.py` 串起 `create_run` + `execute_run`，
支持 `--final-top-k / --candidate-top-k / --min-score / --crag / --multi-query /
--no-rerank / --no-graph / --generation`。Makefile 加 `eval-run` / `eval-ab` / `eval-breakdown`。

### 3. 踩坑：HF 离线

`sentence-transformers` 即使有本地缓存，加载时仍会联网校验 `adapter_config.json`；
本机 huggingface.co 不可达 → 整轮评测 80 条全 fail。
**必须设 `HF_HUB_OFFLINE=1`**（或 `HF_ENDPOINT=https://hf-mirror.com`）。
已写进 `.env.example`。

### 4. 最终数字（80 条，0 报错）

### 5. 三条值得记住的结论

- **Recall@10 == Recall@5（50.0%/50.0%）**，天花板是 `final_top_k=5` 不是检索器。
  26 条上看到过，80 条上复现 → 不是小样本噪声。
- **原 22 条在新一轮里 Recall@5=52.3%、MRR=0.417，和上一轮一字不差** → 系统没退化，
  且这套评测可重复。headline 掉的点全部来自新增用例（平均 gold 块数 1.96 vs 1.73）。
- **误拒答 5 条的 recall@5 与 hit@5 全是 0** → 生成层在空上下文下说「没有」是正确行为，
  锅在检索不在 prompt。已排除索引缺失（DB 2986 = Chroma 2986）。
  70 条可答里 22 条（31%）recall@5=0 → **行动项是修召回，不是动 prompt**。
